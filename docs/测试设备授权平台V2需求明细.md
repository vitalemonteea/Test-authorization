# 测试设备授权平台 V2 需求明细

> 文档版本：V2.0  
> 更新时间：2026-07-28  
> 范围来源：`docs/测试设备授权平台V2需求概述.md`  
> 目标读者：负责生成测试规格、编写自动化测试并执行验证的 AI 代理  
> 适用原型：`测试设备授权平台V2.html`

## 0. 文档定位

### 0.1 目标

1. 将需求概述拆解为可定位、可复现、可断言的详细需求。
2. 为 AI 生成自动化测试规格提供稳定的需求 ID、前置状态、Mock 输入和预期结果。
3. 让每个测试失败都能回溯到唯一验收标准，而不是依赖 AI 对页面文案的主观理解。

### 0.2 范围

1. 本文档包含三个页面域：申请产品授权、授权记录、移动端适配。
2. 不描述独立的“申请 XaaS 授权”页面。
3. 授权记录中的 XaaS 查询、详情、复制、审核及移动端适配属于本期范围。
4. V3 规划、真实审批流、真实授权开通、外部系统接口和生产权限模型不属于本期范围。
5. 原型中的审批计算仅用于生成页面状态和提交快照；申请人页面不得展示内部审批路线预览。

### 0.3 权威来源优先级

发生冲突时按以下顺序处理：

1. 本文档中的需求与验收标准。
2. `authorization-application-rules.js` 中的可计算规则合同。
3. `docs/Mock数据使用手册.md` 中的可复现数据。
4. `测试设备授权平台V2.html` 中的当前选择器和页面结构。
5. `docs/测试设备授权平台V2需求概述.md` 中的范围定义。

`测试授权V2.md`、`需求描述.md` 和旧版原型仅为历史资料，不得作为自动化测试断言来源。特别是“用户手动选择授权场景”的旧设计已经失效，当前授权场景必须由设备事实自动识别。

### 0.4 AI 测试执行合同

1. 每个测试名称必须包含至少一个验收标准 ID，格式为 `[AT-页面域-模块号-用例号]`。
2. 纯规则测试使用 Node `node:test` 直接测试 `authorization-application-rules.js`。
3. DOM 交互测试优先复用 `tests/helpers/load-v2-dom.cjs`，不得复制一套新的页面加载器。
4. 只有视口尺寸、冻结列、响应式显隐等无法通过稳定 DOM 状态判断的场景才使用 Playwright。
5. 测试数据必须来自本文档第 5 章或 `docs/Mock数据使用手册.md`，不得随机生成设备历史。
6. 测试必须断言用户可观察结果；只有规则合同、提交快照和隐藏状态字段允许断言内部数据。
7. 不得通过删除断言、降低断言强度、写死异步等待时间或修改 Mock 结果来让失败测试通过。
8. 完成规格后运行 `npm test`。任何失败需报告：测试 ID、关联需求 ID、实际结果、预期结果和失败分类。
9. 当前基线为 141 个测试全部通过；新增需求不得造成既有用例回归。

### 0.5 优先级定义

| 优先级 | 含义 | 执行要求 |
| --- | --- | --- |
| P0 | 核心申请、阻断规则、提交数据、关键记录操作 | 每次变更必须执行 |
| P1 | 筛选、联动、详情完整性、移动端适配、可访问性 | 合并前必须执行 |
| P2 | 纯视觉细节、非关键提示、预留入口 | 按涉及范围执行 |

## 1. 通用业务合同

### 1.1 核心状态

| 状态字段 | 取值 | 业务含义 |
| --- | --- | --- |
| `authorizationStatus` | `none` | 当前范围内没有历史授权，识别为首次开通 |
| `authorizationStatus` | `expired` | 有历史但无有效授权，识别为重新开通 |
| `authorizationStatus` | `active` | 存在有效授权，识别为调整当前测试授权 |
| `baseScene` | `first_open` | 首次开通测试授权 |
| `baseScene` | `reopen` | 重新开通测试授权 |
| `baseScene` | `adjust` | 调整当前测试授权 |
| `requestContents` | `extend` | 延长授权时间 |
| `requestContents` | `add_module` | 增开模块 |
| `requestContents` | `increase_capacity` | 扩大容量或规格 |
| `overdueTier` | `normal` / `overdue` | 累计测试是否超过规则阈值 |

### 1.2 历史范围与阈值

| 产品范围 | 历史匹配口径 | 单次上限 | 累计上限 | 其他限制 |
| --- | --- | --- | --- | --- |
| 默认产品 | 客户 + 产品线 + 设备标识 | 普通客户 90 天；KA 180 天 | 180 天 | 有效授权可延期、增开模块、扩容 |
| HCI、SCP | 客户 + 产品线 + 集群标识 | 普通客户 90 天；KA 180 天 | 180 天 | 必须上传 `.info`；容量自助上限 20 |
| aTrust | 默认口径 | 普通客户 90 天；KA 180 天 | 180 天 | 容量自助上限 500；销售设备增开模块升级审批 |
| XDR | 仅设备标识 | 普通及 KA 均 90 天 | 90 天 | 第二次申请进入更高规则处理 |
| WOC | 默认口径 | 普通客户 90 天；KA 180 天 | 180 天 | 已退市但仍允许申请 |

1. “授权已过期”和“累计测试超期”是两个独立状态，可以同时成立。
2. 销售设备、借测设备、客户自有设备是来源属性，不替代首次、重新开通、调整三个基础场景。
3. 同一设备可以跨客户、跨批次重复使用；切换客户后必须按新历史范围重新识别。

## 2. 申请产品授权页面

### 2.1 产品线与版本 `[REQ-PA-01]`

#### 1、初始状态

1. 产品线和版本位于基本信息首行，桌面端为两列，移动端为单列。
2. 默认产品线为 HCI，版本下拉展示 HCI 对应版本。
3. 产品线下拉分为“在售产品”和“已退市产品”；已退市区位于列表底部。
4. 当前仅 WOC 为已退市产品，仍保持可选择，退市标签显示在选项右侧。
5. 产品线触发器展开后在原位置切换为搜索输入，不额外叠加第二个搜索框。

#### 2、交互逻辑说明

1. 输入产品名称时同时过滤在售和已退市分区；无匹配项时显示“未找到匹配产品”。
2. 选择产品线后关闭下拉、同步触发器文案、刷新版本列表和授权模块。
3. 选择 WOC 后在字段下方持续显示退市风险提示；切换至在售产品后隐藏。
4. 切换产品线必须清除设备 ID/SN、硬件文件识别结果、设备事实、授权场景、申请内容、兼容性问题和提交快照。
5. aTrust 展示 8 个真实版本选项，NGAF 展示 2 个真实版本选项；切回 HCI 时恢复 HCI 版本集合。

#### 3、字段校验规则

1. 产品线和版本必须始终存在有效选中值。
2. 搜索只影响显示结果，不修改已选值；关闭未选择时保持原值。
3. 长版本文案允许换行，不得产生下拉面板横向滚动。

#### 4、提交逻辑处理

1. 提交产品线 ID、产品状态和版本值。
2. 退市状态只追加风险原因，不单独阻断提交或改变审批路线。

#### 5、验收标准

1. `[AT-PA-01-01][P0]` Given 默认加载页面，Then 产品线为 HCI，设备 ID 与申请类型隐藏，硬件信息文件显示。
2. `[AT-PA-01-02][P1]` Given 展开产品线，When 搜索 `WOC`，Then 仅退市分区保留 WOC 且右侧显示退市标签。
3. `[AT-PA-01-03][P1]` Given 选择 WOC，Then 下拉关闭后风险提示仍显示；When 切换在售产品，Then 提示隐藏。
4. `[AT-PA-01-04][P0]` Given 已识别设备，When 切换产品线，Then 旧设备事实、场景、申请内容和快照全部失效。
5. `[AT-PA-01-05][P1]` Given 分别选择 aTrust、NGAF、HCI，Then 版本集合分别为 8 项、2 项和 HCI 原集合。

### 2.2 客户与组织信息 `[REQ-PA-02]`

#### 1、初始状态

1. 客户信息位于产品线/版本之后、申请类型和设备信息之前。
2. 客户搜索框支持按客户名称检索；选中后展示客户名称、客户类型和销售负责人。
3. 客户编码仅用于内部匹配，不在页面任何可见区域展示。
4. 区域与办事处为两列；接收邮箱为整行单输入框。
5. 接收邮箱占位提示为“请输入接收邮箱，建议优先填写客户邮箱”。

#### 2、交互逻辑说明

1. 更换客户时清除旧客户选择状态并重新开放搜索。
2. 客户变化后必须按新客户重新查询当前设备历史并重新派生场景、超期状态和内部审批决策。
3. 普通客户授权日期上限为 90 天，KA 客户为 180 天；XDR 对两类客户均为 90 天。
4. 用户可以填写本人邮箱或客户邮箱，当前只支持一个邮箱地址。

#### 3、字段校验规则

1. 客户必须具有可识别的客户 ID、客户类型和客户名称后才能形成确定性历史范围。
2. 接收邮箱为空时不做格式校验；填写时必须是单个合法邮箱，不接受逗号或分号分隔的多个地址。
3. 日期不得超过当前客户及产品对应的单次上限；客户类型改变后必须立即重算。

#### 4、提交逻辑处理

1. 提交客户 ID、客户名称、客户类型、区域、办事处和单个接收邮箱。
2. 客户编码不得作为页面展示字段写入只读摘要。

#### 5、验收标准

1. `[AT-PA-02-01][P1]` Given 选择 `C100001`，Then 显示 KA、销售负责人和 180 天上限，不显示 `C100001`。
2. `[AT-PA-02-02][P1]` Given 选择普通客户 `C100004`，Then 日期上限为 90 天。
3. `[AT-PA-02-03][P0]` Given `SOFT-REOPEN-001` 在 `C100001` 下为重新开通，When 切换至无历史客户，Then 重新识别为首次开通。
4. `[AT-PA-02-04][P1]` Given 邮箱输入包含两个地址，Then 校验失败；Given 单个本人邮箱，Then 允许继续。

### 2.3 授权对象录入 `[REQ-PA-03]`

#### 1、初始状态

1. HCI、SCP 使用硬件信息文件识别模式：隐藏申请类型、设备 ID 和设备 SN，只显示硬件信息文件。
2. 其他产品显示申请类型，取值为硬件借测和纯软测试。
3. 非 HCI/SCP 产品的设备 ID、设备 SN 均使用多 Chip 输入并占据整行。
4. 硬件借测显示借测单号、借测使用人、借测状态和借测类型；纯软测试隐藏借测信息。
5. 硬件信息文件位于客户信息之后、申请类型或设备输入之前。

#### 2、交互逻辑说明

1. 输入 ID 或 SN 并回车后生成 Chip，同一字段内重复值不得重复添加。
2. 删除设备 ID 时同步删除对应 SN、设备事实和派生状态；删除最后一个设备后隐藏授权场景和申请内容。
3. 硬件借测输入命中借测单的设备后，自动带出同借测单全部设备及借测信息；用户可以删除不参与本次申请的设备。
4. 纯软测试只查询授权历史，不校验客户自有设备资产是否登记。
5. HCI/SCP 上传 `.info` 后生成集群设备事实；不得通过旧设备 ID 接口写入设备。

#### 3、字段校验规则

1. HCI/SCP 硬件信息文件必填且仅接受 `.info` 后缀。
2. 普通硬件借测必须有设备 ID/SN 和四项借测信息；未匹配借测资产时直接阻断。
3. 纯软测试允许任意非空 ID 或 SN；无设备资产记录且无历史时按首次开通，不显示“待人工确认”。
4. 查询到的实际产品与所选产品不一致时阻断，并显示设备及实际产品名称。

#### 4、提交逻辑处理

1. HCI/SCP 提交由文件派生的集群标识和设备事实，不要求可见设备 ID/SN 字段。
2. 普通产品只提交当前仍保留的 ID/SN 和借测信息。
3. 被隐藏模式的字段禁用且不得进入提交数据。

#### 5、验收标准

1. `[AT-PA-03-01][P0]` Given HCI 或 SCP，Then 仅显示硬件信息文件；When 上传合法 `.info`，Then 生成设备事实并可继续。
2. `[AT-PA-03-02][P0]` Given NGAF 硬件借测，When 输入 `DEV-NGAF-001`，Then 自动带出 `DEV-NGAF-002` 和 `BT20240615002`。
3. `[AT-PA-03-03][P0]` Given 硬件借测，When 输入 `UNKNOWN-BORROWED-001`，Then 阻断且不显示人工确认入口。
4. `[AT-PA-03-04][P0]` Given 纯软测试，When 输入 `UNKNOWN-001`，Then 直接识别首次开通且无人工确认提示。
5. `[AT-PA-03-05][P0]` Given 选择 aTrust，When 输入实际为 NGAF 的 `DEV-NGAF-001`，Then 显示产品不一致并阻断。

### 2.4 设备事实与授权场景 `[REQ-PA-04]`

#### 1、初始状态

1. 未识别设备时不展示授权场景、申请内容和设备事实卡片，不占据布局空间。
2. 授权场景是系统派生的只读业务字段，用户不能手动选择。
3. 每台设备使用独立、默认收起的事实卡片；卡片标题展示设备标识和当前授权状态。
4. 展开后展示来源、授权中台、累计测试、历史申请和最新授权有效期。
5. 当前模块和当前容量不在事实卡重复展示，统一在授权配置卡片中体现；“识别依据”不展示。

#### 2、交互逻辑说明

1. 无历史识别为首次开通，申请内容固定为开通测试授权。
2. 有已结束历史且无有效授权识别为重新开通，申请内容固定为重新开通授权。
3. 有有效授权识别为调整当前测试授权，可选择延期、增开模块、扩大容量/规格。
4. 有效期内销售设备仍属于调整场景，并显示“销售设备”标签及三项申请内容。
5. 多设备只有基础场景一致时才展示共同场景，否则进入拆单提示。

#### 3、字段校验规则

1. 首次和重新开通的固定申请内容不可取消。
2. 调整场景至少选择一项申请内容，三项可组合。
3. 查询超时、硬件未知、产品不一致时不得生成可提交场景。

#### 4、提交逻辑处理

1. 提交派生的 `baseScene`、内部申请动作、申请内容和设备事实。
2. 页面展示场景与内部状态必须来自同一次设备事实版本。

#### 5、验收标准

1. `[AT-PA-04-01][P0]` Given `SOFT-FIRST-001`，Then 场景为首次开通且申请内容固定。
2. `[AT-PA-04-02][P0]` Given `SOFT-REOPEN-001`，Then 场景为重新开通且不展示识别依据。
3. `[AT-PA-04-03][P0]` Given `ACTIVE-NGAF-001`，Then 场景为调整并展示三项可组合内容。
4. `[AT-PA-04-04][P0]` Given `SALES-ATRUST-001`，Then 展示销售设备标签和延期、增开模块、扩容三项。
5. `[AT-PA-04-05][P1]` Given 已识别设备，When 删除最后一个设备，Then 事实卡、场景、申请内容和旧决策全部清空。

### 2.5 超期与特殊申请补充 `[REQ-PA-05]`

#### 1、初始状态

1. 只有累计测试达到超期层级时显示审批提示、申请理由和证明材料。
2. 审批提示固定表达“升级审批”和“扣除区域经营成本”。
3. 申请理由为多行输入；证明材料为单文件上传，当前文件格式尚未确认。

#### 2、交互逻辑说明

1. 超期判定使用历史累计时长加本次申请时长，与产品及客户阈值比较。
2. 重新开通和累计超期可以同时显示；不得把“已过期”直接等同于“累计超期”。
3. 从超期设备切换或删除至非超期状态时，隐藏并清空补充信息。

#### 3、字段校验规则

1. 超期状态下申请理由必填，去除首尾空格后不得为空。
2. 证明材料当前为选填；在格式和必填性确认前，AI 不得生成后缀白名单或强制上传测试。
3. 非超期状态下补充字段不参与校验和提交。

#### 4、提交逻辑处理

1. 超期提交包含申请理由和已选择的证明材料元数据。
2. 超期不直接禁止申请，而是生成升级审批决策；明确禁止自助的设备仍优先阻断。

#### 5、验收标准

1. `[AT-PA-05-01][P0]` Given `OVERDUE-NGAF-001`，Then 同时显示重新开通、累计测试超期、升级审批和经营成本提示。
2. `[AT-PA-05-02][P0]` Given 超期状态且申请理由为空，When 提交，Then 聚焦理由字段并阻断。
3. `[AT-PA-05-03][P1]` Given 已填写理由且未上传材料，Then 不因未知文件规则而阻断。
4. `[AT-PA-05-04][P1]` Given 超期状态，When 删除超期设备，Then 补充区域隐藏并清空。

### 2.6 多设备兼容与拆单 `[REQ-PA-06]`

#### 1、初始状态

1. 兼容性区域默认隐藏，仅在存在冲突时显示于设备 ID 下方。
2. 冲突信息逐条点名冲突设备和原因，不展示空面板。

#### 2、交互逻辑说明

1. 比较产品线、基础场景、申请动作、申请内容、超期层级、设备来源、借测单、材料集合、决策类型和审批路线。
2. 任一项不一致均为硬冲突，要求拆单。
3. 同借测单自动补齐的设备允许成对删除 ID/SN，删除后立即重算兼容性。

#### 3、字段校验规则

1. 存在硬冲突时禁止提交。
2. 两台及以上设备兼容时不得显示拆单提示。
3. 设备事实版本变化后原兼容性结果失效，必须重新查询。

#### 4、提交逻辑处理

1. 拆单是申请级阻断，不生成成功提示和提交快照。
2. 成功提交仅包含用户最终保留的设备。
3. 多设备不允许在一个申请中生成多条授权记录，若业务需多条记录必须拆单。

#### 5、验收标准

1. `[AT-PA-06-01][P0]` Given 同借测单、同场景和同路线设备，Then 兼容且可提交。
2. `[AT-PA-06-02][P0]` Given 不同借测单或不同基础场景，Then 点名冲突设备并要求拆单。
3. `[AT-PA-06-03][P0]` Given 自动补齐两台设备，When 删除一台，Then ID/SN 同步删除且快照仅保留另一台。
4. `[AT-PA-06-04][P0]` Given 事实版本已变化，Then 提交提示重新查询而非沿用旧快照。

### 2.7 授权配置 `[REQ-PA-07]`

#### 1、初始状态

1. 授权模块以独立卡片展示，每张卡包含开关、模块名称、状态、有效期及参数输入。
2. 已授权模块默认开启，显示“已授权”和当前有效期；未授权模块显示“未授权”。
3. 已有模块和容量只在本区域展示，不在设备事实卡重复。
4. 提供全部展开和全部折叠操作；模块卡片不嵌套到其他卡片中。

#### 2、交互逻辑说明

1. 首次或重新开通显示日期与模块配置。
2. 调整场景选择延期时显示日期；选择增开模块或扩容时显示模块配置；组合选择时同时显示。
3. 关闭模块后折叠其配置并排除校验；重新开启后恢复可编辑状态。
4. 统一授权日期可应用到所有已启用模块。
5. 当前已授权模块在加载设备事实后映射为开启状态、授权状态和有效期。

#### 3、字段校验规则

1. 已禁用模块字段不参与校验。
2. 授权日期不得超过客户及产品单次上限。
3. HCI/SCP 目标容量超过 20、aTrust 超过 500 时升级审批但不直接阻断。
4. 只有申请内容包含扩容时，目标容量才参与审批计算。

#### 4、提交逻辑处理

1. 仅提交已启用模块及其有效参数、容量和日期。
2. 提交时保留当前模块的变更前状态，以供授权记录详情展示配置变更。

#### 5、验收标准

1. `[AT-PA-07-01][P0]` Given HCI 有效授权文件 `HCI-active-demo.info`，Then 计算虚拟化、分布式存储默认开启并显示有效期，当前容量为 16。
2. `[AT-PA-07-02][P0]` Given 调整场景，When 仅选择延期，Then 显示日期而隐藏无关模块配置。
3. `[AT-PA-07-03][P0]` Given 关闭某模块，Then 该模块字段不参与校验和提交。
4. `[AT-PA-07-04][P1]` Given 选择统一日期，When 应用到所有模块，Then 所有已启用模块日期一致。

### 2.9 底部操作区与提交 `[REQ-PA-09]`

#### 1、初始状态

1. 底部为粘性操作区，包含状态提示、重置和“立即获取”。
2. 初始状态提示“请先识别设备或上传硬件信息”。
3. 内部审批预览节点保持隐藏，不向申请人展示路线或审批人。

#### 2、交互逻辑说明

1. 有效期内设备识别完成但未选申请内容时提示“请选择申请内容”。
2. 信息完整时提示“已识别 N 台设备，可以提交”。
3. 查询超时时展示重试和保存草稿；重试重新查询，保存草稿不生成成功提交快照。
4. 重置清除全部表单、设备事实、决策、冲突和快照，并恢复默认 HCI 文件模式。

#### 3、字段校验规则

提交依次校验：HCI/SCP 文件及后缀、查询阻断、设备兼容性、设备事实存在、场景已识别、调整事项已选择、超期理由、申请类型、硬件 SN 与借测字段、规则版本、事实版本。任一失败立即停止，不生成快照。

#### 4、提交逻辑处理

1. 明确禁止自助时提示联系管理员并阻断。
2. 成功时生成深复制快照，包含产品线、产品状态、基础场景、申请动作、申请内容、授权场景、设备事实、审批决策和规则版本。
3. 规则版本变化或事实陈旧时要求重新识别，不允许使用旧结果提交。
4. 原型成功只表示前端模拟提交完成，不代表真实审批或授权已开通。

#### 5、验收标准

1. `[AT-PA-09-01][P0]` Given 查询超时 `ERR-TIMEOUT-001`，Then 阻断场景和提交，并显示重试、保存草稿。
2. `[AT-PA-09-02][P0]` Given `SELF-SERVICE-BLOCKED-001`，When 提交，Then 不生成快照或成功提示。
3. `[AT-PA-09-03][P0]` Given 完整合法申请，When 提交，Then 快照包含事实、决策和规则版本且不受后续对象修改影响。
4. `[AT-PA-09-04][P0]` Given 已完成一次申请，When 重置，Then 恢复 HCI 默认模式且旧设备、场景、内容和快照均为空。

### 3.2 记录列表、分页与导出 `[REQ-RC-02]`

#### 1、初始状态

1. 默认可见列为申请编号、授权类型、产品线/方案、版本、客户、设备 ID/云图 ID、区域、有效期、申请人、申请时间、审批状态和操作。
2. 申请平台保留在行数据中但默认隐藏。
3. 申请编号和授权类型固定在左侧，审批状态与操作固定在右侧；固定表头覆盖滚动中的正文列。
4. 默认每页 10 条，可切换 20、50、100 条，并支持上一页、下一页和页码跳转。

#### 2、交互逻辑说明

1. 多设备记录的设备列截断显示，悬浮后展示完整设备 ID 明细。
2. XaaS 记录在设备列直接显示云图 ID。
3. 解决方案记录可展开子设备或子产品明细。
4. 筛选或页容量变化后重新计算页数并保证当前页合法。
5. 导出仅包含当前筛选结果；导出格式尚未确认。

#### 3、字段校验规则

1. 页码必须为有效整数，超出范围时回到最近有效页。
2. 导出格式未确认前，仅生成“入口存在、使用当前筛选集”的测试，不断言文件后缀或列格式。

#### 4、提交逻辑处理

列表查询和分页不修改记录；导出使用当前过滤后的完整结果，不仅限当前页。

#### 5、验收标准

1. `[AT-RC-02-01][P1]` Then 申请平台列默认隐藏但数据解析仍可读取。
2. `[AT-RC-02-02][P1]` Given XaaS 记录，Then “设备 ID/云图 ID”列显示云图 ID。
3. `[AT-RC-02-03][P1]` Given 横向和纵向滚动，Then 固定表头及右侧状态/操作不被正文覆盖。
4. `[AT-RC-02-04][P1]` When 切换每页条数或跳页，Then 信息文本、可见行数和页码一致。

### 3.3 记录操作 `[REQ-RC-03]`

#### 1、初始状态

| 类型/状态 | 可用操作 |
| --- | --- |
| 产品授权/已授权 | 查看、下载、复制、续期 |
| 产品授权/已过期 | 查看、下载、续期 |
| 产品授权/待审批、审批中、已通过 | 查看 |
| 产品授权/已驳回 | 查看、重新提交 |
| XaaS/待审批 | 审核、撤销 |
| XaaS/已授权 | 查看、下载、复制、续期 |
| 解决方案/已授权 | 查看、下载、复制、续期 |
| 解决方案/已驳回 | 查看、重新提交 |

#### 2、交互逻辑说明

1. 下载只对已授权和已过期记录显示，生成一个不预设扩展名的 Mock 授权文件。
2. 复制产品授权跳转产品申请页并回填产品、版本、客户、区域、日期及可复用设备信息。
3. 复制 XaaS 跳转 XaaS 申请页并回填联系人、客户、行业、订阅产品、规格和业务补充信息。
4. 不熟悉的操作在悬浮和键盘聚焦时显示功能说明；查看不重复显示说明。

#### 3、字段校验规则

1. 不符合状态的操作不得渲染，不能只通过禁用样式隐藏。
2. 复制只回填可复用信息，不复制原申请编号、审批结果和开通结果。

#### 4、提交逻辑处理

下载、复制、续期、重提、审核和撤销完成后提供明确结果提示；原型只更新页面演示状态。

#### 5、验收标准

1. `[AT-RC-03-01][P0]` Then 只有已授权、已过期记录存在下载按钮。
2. `[AT-RC-03-02][P0]` Given HCI 产品记录，When 复制，Then 跳转产品申请页并回填 HCI、历史版本、客户、区域和日期。
3. `[AT-RC-03-03][P0]` Given SASE-GA XaaS 记录，When 复制，Then 跳转 XaaS 页并回填联系人、行业、产品规格及业务补充信息。
4. `[AT-RC-03-04][P1]` Then 每种非查看操作的提示文案和可访问名称一致。

### 3.4 详情侧边抽屉 `[REQ-RC-04]`

#### 1、初始状态

1. 查看使用右侧抽屉，不离开或替换授权记录列表。
2. 抽屉统一宽度、标题、摘要、只读表单和分区样式。
3. 产品授权依次展示申请信息、客户信息、产品授权明细、业务补充信息、开通结果、审批信息。
4. XaaS 依次展示申请信息、客户信息、订阅授权明细、业务补充信息、开通结果、审批信息。

#### 2、交互逻辑说明

1. 产品授权对象按产品模式显示：HCI/SCP 显示硬件信息文件和集群标识，不显示设备 ID；普通产品显示设备 ID，不显示硬件文件。
2. 产品配置变更以“配置项、变更前、变更后”展示，已开模块、容量和有效期可被判断。
3. 超期记录的升级审批、经营成本、申请原因和附件放在业务补充信息，不混入申请信息。
4. XaaS 展示联系人、云图账号、订阅规格、业务依据、租户/实例标识和授权文件。
5. 点击关闭、遮罩或 Escape 关闭抽屉，关闭后焦点回到触发查看的控件。

#### 3、字段校验规则

只读详情不参与提交；不同授权类型不得出现对方专属字段。

#### 4、提交逻辑处理

不参与数据提交，仅根据当前记录生成展示模型。

#### 5、验收标准

1. `[AT-RC-04-01][P1]` Given 产品授权记录，Then 展示授权对象、配置变更、开通结果和审批时间线。
2. `[AT-RC-04-02][P1]` Given XaaS 记录，Then 展示客户、订阅规格、业务补充信息及租户/实例标识。
3. `[AT-RC-04-03][P1]` Given 超期普通产品，Then 业务补充信息包含升级审批、经营成本、原因和附件。
4. `[AT-RC-04-04][P1]` When 按 Escape 关闭，Then 抽屉隐藏且焦点回到原查看控件。

### 3.5 审核、续期与重新提交 `[REQ-RC-05]`

#### 1、初始状态

1. 三类流程复用与详情一致的侧边抽屉宽度和只读表单样式。
2. 续期展示当前授权有效期、新到期日和续期原因。
3. 重新提交展示上次驳回信息、补充说明和文件上传。
4. 审核按照申请信息、客户信息、授权明细、业务补充信息、已有审批记录、审批决定排列。

#### 2、交互逻辑说明

1. 续期提交成功后关闭抽屉并提示“续期申请已提交”。
2. 重新提交成功后关闭抽屉并提示结果。
3. 审批人必须主动选择通过或驳回，系统不预选；填写审批意见后提交。
4. 审核 XaaS 时展示联系人、行业、订阅规格和业务依据，使审批人能够判断，不仅展示编号与状态。

#### 3、字段校验规则

1. 续期原因必填。
2. 重新提交补充说明必填，材料是否必填按驳回要求；Demo 不限制文件后缀。
3. 审批决定和审批意见必填，缺失时抽屉保持打开并显示错误。

#### 4、提交逻辑处理

1. 原型提交只更新演示结果提示，不定义真实审批节点流转。
2. 审核结果更新当前记录状态时必须保留原申请信息和已有审批记录。

#### 5、验收标准

1. `[AT-RC-05-01][P0]` Given 续期抽屉，When 原因为空提交，Then 保持打开并报错；填写后成功关闭。
2. `[AT-RC-05-02][P0]` Given 已驳回记录，When 填写说明并重新提交，Then 关闭并显示成功提示。
3. `[AT-RC-05-03][P0]` Given 审核抽屉，Then 无默认审批决定；缺决定或意见均阻断。
4. `[AT-RC-05-04][P1]` Given XaaS 审核，Then 六个信息分区顺序固定且包含已有审批记录。

### 3.6 撤销与结果反馈 `[REQ-RC-06]`

#### 1、初始状态

1. 撤销使用独立二次确认弹窗，显示来源申请编号和撤销原因输入框。
2. 结果反馈使用统一 Toast，不改变侧边抽屉宽度或列表布局。

#### 2、交互逻辑说明

1. 未填写原因确认时保持弹窗打开并显示错误。
2. 填写原因确认后关闭弹窗、提示“撤销申请已提交”，焦点回到撤销入口。

#### 3、字段校验规则

撤销原因去除首尾空格后必填。

#### 4、提交逻辑处理

原型只记录演示结果，不调用真实撤销接口。

#### 5、验收标准

1. `[AT-RC-06-01][P0]` Given 撤销弹窗，When 原因为空确认，Then 弹窗不关闭。
2. `[AT-RC-06-02][P1]` Given 有效原因，When 确认，Then 关闭、提示成功并恢复焦点。

## 4. 移动端适配

### 4.1 页面适配 `[REQ-MB-01]`

#### 1、初始状态

1. 移动端不显示桌面导航栏和产品授权右侧模块导航。
2. 产品授权与 XaaS 授权表单采用单列，不出现横向页面滚动。
3. 授权记录取消左右冻结列，页面标题、状态概览、筛选、列表和分页纵向堆叠。
4. 授权记录显示设备 ID/SN 搜索、类型、状态、产品线快捷筛选、完整筛选开关和重置按钮。

#### 2、交互逻辑说明

1. 快捷筛选使用自定义面板，类型、状态和产品线同一时间只展开一个。
2. 选择快捷项后同步完整筛选表单、更新触发器文案、关闭面板并过滤列表。
3. 产品线快捷筛选包含 HCI、SaaS-XDR、SASE-GA 和解决方案等当前记录产品。
4. 重置按钮一次清除快捷与完整筛选并恢复第一页。
5. 完整筛选开关通过 `aria-expanded` 表达展开状态。

#### 3、字段校验规则

1. 移动端与桌面端使用同一筛选数据和校验规则。
2. 快捷筛选不得使用浏览器原生选项弹窗作为可见交互。
3. 所有文字、按钮和 Chip 不得溢出容器或遮挡相邻内容。

#### 4、提交逻辑处理

移动端提交数据与桌面端完全一致，不新增移动端专属业务字段。

#### 5、验收标准

1. `[AT-MB-01-01][P1]` Given 移动端视口，Then 桌面导航和模块导航均不展示，产品表单为单列。
2. `[AT-MB-01-02][P1]` Given 授权记录移动端，Then 取消冻结列且页面纵向堆叠。
3. `[AT-MB-01-03][P1]` When 选择 XaaS 类型和 SaaS-XDR 产品，Then 完整筛选同步且列表仅保留匹配记录。
4. `[AT-MB-01-04][P1]` When 点击扫帚重置，Then 所有条件、文案、状态高亮和分页恢复默认。
5. `[AT-MB-01-05][P1]` When 按 Escape 或点击遮罩，Then 快捷面板关闭并同步 `aria-expanded=false`。

2. `npm test` 全量通过，且无新增控制台错误。

5. 测试失败时先判断实现缺陷、规格缺陷、Mock 缺陷或环境缺陷，再决定修改位置。

## 8. 待确认项与非目标

### 8.1 待确认项

1. 超期证明材料是否必填及允许的文件格式。
2. 授权记录导出的文件格式、字段顺序和文件名规则。
3. 重新提交材料是否根据驳回原因动态必填。
4. 真实接口失败、权限不足、并发提交等生产异常处理。

待确认项在确认前不得生成阻断性自动化测试，只验证入口、显隐和已明确行为。

### 8.2 非目标

1. 不测试独立申请 XaaS 页的完整申请流程；仅测试授权记录和移动端中概述明确保留的 XaaS 行为。
2. 不测试真实审批节点和审批人路由，只测试原型的审核表单与结果反馈。
3. 不测试真实许可证生成、邮件发送、外部系统查询和文件内容解析。
4. 不把隐藏的旧版“当前授权查询”和续期识别区作为主流程入口。
5. 不要求通过 CSS 像素级截图匹配验证功能模块；响应式遮挡、显隐和布局稳定性除外。
