# 基本信息卡片优化设计

## 目标

在不改变现有业务字段、设备查询逻辑和授权场景判断的前提下，优化“基本信息”卡片的信息层级、扫描效率与移动端可读性。参考图仅作为布局层级参考，页面继续使用测试授权 V2 已有的配色、控件和卡片视觉语言。

## 范围

本次只调整“基本信息”卡片的结构与样式，以及设备事实摘要的展示方式。

- 保留所有现有字段及字段名称，包括产品线、版本、申请类型、设备 ID、授权场景、区域、办事处、接收邮箱、客户信息、设备 SN 和借测信息。
- 保留设备 ID 多值 chip 输入、设备查询、产品兼容性判断、授权场景过滤、条件字段显隐和借测信息显隐逻辑。
- 不新增业务字段，不修改审批规则，不修改提交数据结构。
- 不把标题改成“步骤1”，因为当前页面不是分步表单。

## 信息结构

### 卡片标题

标题继续使用“基本信息”。标题下方增加短蓝色强调线和浅色延伸线，强化当前区域的视觉层级，但颜色、圆角和阴影保持与 V2 其他模块协调。

### 基础选择

- 产品线与版本在桌面端保持两列排列。
- 申请类型单独占一行，桌面端控件区域为半栏宽，避免与设备信息混在同一层级。
- 移动端上述字段全部改为单列，标签位于控件上方。

### 设备识别

设备 ID 输入区保持全宽，并继续支持多设备 chip。设备查询结果紧跟在输入区下方，每台设备显示为一个独立的浅蓝色事实面板。

事实面板顶部显示设备 ID 与授权状态；下方展示现有数据中已经存在的七项事实：

1. 实际产品
2. 来源
3. 授权状态
4. 当前模块
5. 当前容量
6. 累计测试
7. 历史申请

桌面端事实项使用自适应网格排列，不能依赖固定单设备宽度；移动端使用两列网格，较长内容允许换行。多设备时面板纵向堆叠。未查询到数据、查询失败和产品不一致仍沿用现有提示与阻断规则。

授权状态文案使用现有业务状态“有效授权”“授权已过期”“无授权”，不使用没有数据依据的“激活”状态。

### 申请归属

授权场景、区域和办事处在桌面端组成三列行，标签位于控件上方；移动端依次折为单列。授权场景仍由设备事实过滤后供用户选择。

续期、扩容或其他根据场景出现的条件字段继续作为独立全宽区域展示，不嵌入三列行，也不改变当前显隐顺序。

### 联系与设备补充信息

接收邮箱、客户信息和设备 SN 保持全宽排列。客户搜索、客户信息回显和设备 SN 回车添加交互保持不变。

### 借测信息

借测信息继续只在申请类型需要时显示。子区采用正常文档流中的标题和轻描边容器，不再让标题通过负边距压在边框上。

桌面端四个借测字段采用 2×2 网格，移动端为单列。字段校验、默认值和显隐逻辑保持不变。

## 视觉规则

- 延续 V2 的蓝色主色、浅色卡片背景、现有输入框和下拉框样式。
- 卡片和子区圆角不超过现有设计系统的尺度，不引入新的渐变或装饰性背景。
- 减少基本信息卡片内不必要的纵向空白，字段组间距保持一致。
- 设备事实面板使用浅蓝底和轻描边；事实项使用接近白色的轻量分区，不形成嵌套装饰卡片感。
- 标签、状态和事实值保证长文本可换行或省略，不能撑破容器。

## 响应式行为

- 桌面端：产品与版本两列；申请类型半栏；设备 ID、条件字段及联系信息全宽；归属信息三列；借测信息 2×2。
- 移动端：所有表单字段单列；设备事实项两列；借测信息单列。
- 在现有移动断点下切换布局，不新增基于视口宽度缩放字号的规则。

## 测试策略

先更新布局测试，使其对新结构失败，再实现布局与渲染：

- 结构测试覆盖标题强调、申请类型半栏、归属三列、设备事实面板七项和借测子区结构。
- 交互测试覆盖设备查询后事实面板的内容、多个设备的独立面板，以及清空或切换产品后摘要重置。
- 回归现有产品退市分组、授权场景过滤、多设备兼容性、HCI 初始化和 Logo 资源测试。
- 浏览器验证桌面和移动视口，检查字段不重叠、长文本可读、设备事实面板在初始态不产生空白占位，并检查控制台无错误。

## 验收标准

1. 基本信息卡片保留全部现有字段和业务交互，没有新增申请字段。
2. 设备 ID 查询成功后，每台设备以独立事实面板展示七项已有事实。
3. 桌面端和移动端布局符合本设计的列数与折行规则，内容无重叠和溢出。
4. 授权场景仍由设备数据过滤，并由用户主动选择。
5. 借测信息继续按申请类型显隐，字段与校验不变。
6. 初始页面、产品切换和设备清空后不显示陈旧设备事实。
7. 所有自动化测试通过，浏览器控制台没有页面错误。
