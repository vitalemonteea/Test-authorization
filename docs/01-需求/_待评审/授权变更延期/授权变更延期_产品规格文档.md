## 1. 背景与问题陈述（Why）

当前客户可通过**测试授权申请平台**提交试用申请；开通后如有变动，可**再次提交申请**来延期或追加已开通的授权。

**核心问题**：再次提交的申请内容不完整——审批人在审核时**无法识别本次相对已开通授权到底改了什么**（延长了多久、规格调了多少），只能凭经验或线下沟通去核对，造成审批效率低、易漏审、易退回。

**本次目标**：在"变更 / 延期试用"申请场景中，让变更内容对审批人**可见、可读、可追溯**——在授权记录页以"配置项 / 变更前 / 变更后"配置变更表展示变更点，并支持查看关联的此前申请记录。

---

## 2. 目标与非目标

### 目标

1. 审批人在审核页可一眼识别本次申请的变更点（变更字段、变更前后值）。
2. 变更点以"配置项 / 变更前 / 变更后"表格呈现，模块按订阅分组、默认收起，便于快速浏览。
3. 审批人可下钻查看本次申请关联的此前授权申请记录，获得历史上下文。
4. 首次开通的 XaaS 授权记录沿用同一配置变更表，保持阅读体验一致。

### 非目标（Non-goals）

1. 不改造申请提交流程本身，不改变"再次提交申请"的入口与字段填写方式。
2. 不做审批流引擎改造（审批动作、审批人分配规则不在本次范围）。
3. 不在首次开通场景引入"原值对比"逻辑：首次开通仅以"未开通 / —"作为变更前值，展示申请后的配置。
4. 不做变更内容的自动校验或冲突拦截（仅展示，不阻断）。
5. 不改申请人提交页的既有展示（申请人端"新值 + 原值"对比已存在，本次仅补审批端能力）。
6. 不改造产品授权记录既有的配置变更表；解决方案 / 设备授权记录的展示不在本次范围。
7. 不引入字段级权限；高亮与关联记录的可见性由审批页权限控制。

## 3. 角色与术语

### 角色

| 角色 | 说明 |
| :--- | :--- |
| 授权审批人 | 审核测试授权申请的人员（具备授权审批权限） |
| 申请人 | 提交授权申请的人员（客户 / CSM / 销售，代客户提交） |

### 术语

| 术语 | 说明 |
| :--- | :--- |
| 变更 / 延期试用 | 申请动作之一，表示在已开通授权基础上发起部分内容变更 |
| 申请动作 | 表单层动作，取值「变更 / 延期试用」；仅用于展示判定，不用于审批路由 |
| 审批场景 | 路由层细分场景（延期 / 授权变更 / 新增模块等）；仅用于审批流，不影响展示判定 |
| 原值 | 当前**已生效授权**中对应字段的值（变更对比的基准）；首次开通场景无原值，按"未开通 / —"展示 |
| 配置变更表 | 记录页"订阅授权明细"下的对比表，列为"配置项 / 变更前 / 变更后"；订阅级配置项直接成行，模块级配置按订阅分组、默认收起 |
| 首次开通 | 申请动作为"首次开通试用"，无已生效授权；配置变更表的变更前值为"未开通"或"—" |
| 关联此前申请记录 | 与本次申请属于同一 **XaaS 订阅 ID**、在本次之前提交的授权申请记录；以申请编号作为查看详情的查询键 |

## 4.1 授权变更 / 延期可视化（EP-01）

> 本次配置变更展示覆盖 XaaS 订阅记录（含首次开通与变更 / 延期）；产品授权沿用既有配置变更表，解决方案 / 设备授权不在范围内。

### 4.1.1 配置变更表展示（变更 / 延期）

#### 1、初始状态

1. 审批人打开"变更 / 延期试用"的 XaaS 授权记录审核页或详情页。
2. "订阅授权明细"下展示"配置变更"表，表头固定为"配置项 / 变更前 / 变更后"。
3. 表格上方为订阅级配置项（如授权有效期）；下方按订阅展示模块分组。
4. 模块分组默认收起，行内左侧为模块名称，右侧为"N 项变更 · 至 YYYY-MM-DD"与展开图标。
5. 变更后值使用深蓝加粗强调，变更前值为普通文本。
6. 未发生变化的配置项不进入表格。

#### 2、交互逻辑说明

1. 进入记录页后，系统按申请动作渲染配置变更表；变更 / 延期记录展示真实的前后值。
2. 订阅级配置项直接成行；模块级配置按订阅分组，一行一个模块。
3. 点击模块行展开参数明细，再次点击收起；展开状态不跨记录保留。
   a. 展开项按"模块状态、版本、产品参数、授权至"的顺序展示。
   b. 订阅无对应字段时不生成空行。
4. 多订阅记录逐条分组（如 NGDR 的"PC 终端""服务器"），每组独立展开 / 收起。
5. 审批抽屉与详情抽屉使用同一配置变更表与交互。
6. 配置变更表下方按 4.1.2 展示"关联此前申请记录"。

#### 3、字段校验规则

1. 展示字段白名单：
   a. 授权有效期；
   b. 订阅 `meta` 中的业务参数；
   c. 模块 / 订阅增删；
   d. 模块状态、版本、授权至。
2. 不展示字段：订阅状态、授权码、租户 ID、交付信息、申请理由、附件、联系人。
3. 变更前值取当前已生效授权值；上一笔审批通过但未生效的变更不进入基准。
4. 原值缺失或格式异常时，变更前显示"—"，不阻断展示。
5. 日期格式统一为 `YYYY-MM-DD`；有效期区间为 `YYYY-MM-DD ~ YYYY-MM-DD`。
6. "N 项变更"按展开项数量计数，包含模块状态、授权至。
7. 本模块为只读展示，无用户输入项，无独立输入校验。

#### 4、提交逻辑处理

1. 本模块不涉及表单提交，不新增提交接口。
2. 审批通过 / 驳回 / 转签沿用现有审批流程与权限控制。
3. 配置变更表仅随记录查询结果渲染，不写回授权数据。
4. 不做字段级权限；可见性由审批页权限控制。

#### 5、验收标准

1. 配置变更表展示：
   a. 变更 / 延期记录展示"配置项 / 变更前 / 变更后"三列表头。
   b. 授权有效期行展示变更前后日期，变更后值深蓝加粗。
   c. 模块分组默认收起，摘要为"N 项变更 · 至 YYYY-MM-DD"；点击可展开 / 收起。
   d. 展开项包含模块状态、版本、产品参数、授权至；未变化字段不展示。
2. 多订阅与一致性：
   a. 多订阅记录逐条分组，各自独立展开 / 收起。
   b. 审批抽屉与详情抽屉展示一致。
   c. 原值缺失时变更前显示"—"，页面不报错。
   d. 不具备审批权限的角色不可见。

### 4.1.2 关联此前申请记录

#### 1、初始状态

1. 配置变更表下方展示"关联此前申请记录"区，按订阅分组，组头为"产品族 / 订阅名称"，默认展开。
2. 组头右侧展示折叠图标，组头同时作为该组表格的收起 / 展开控制，不再单独展示"查看关联此前申请记录"入口行。
3. 首次开通记录无历史申请，不展示该区。
4. 组内表格列为"申请编号 / 申请人 / 区域 / 申请时间 / 授权产品 / 到期时间 / 操作"，不再展示"模块""参数规格"。
5. 每行"操作"列展示"查看"按钮，用于打开该申请编号对应的历史授权记录详情。

#### 2、交互逻辑说明

1. 点击组头收起该组表格，再次点击展开；默认展开。
2. 多订阅记录逐组展示，每组独立展开 / 收起，展开状态不跨记录保留。
3. 展开后按申请时间正序展示历史申请；每行展示申请编号、申请人、区域、申请时间、授权产品、到期时间。
4. 点击"查看"按钮，打开该申请编号对应的历史授权记录详情；详情抽屉展示申请信息、客户信息、订阅授权明细、业务补充信息与开通结果。
   a. 历史记录为首次开通：详情按首次开通口径展示，变更前为"未开通 / —"。
   b. 历史记录为变更 / 延期：详情按当次变更口径展示变更前后值。
   c. 历史详情标题为"历史申请详情"，抽屉底部展示"返回审核申请"入口。
   d. 点击"返回审核申请"回到当前审批申请，保留已填写的审批意见、审批决定、附件、展开状态与滚动位置；查看其他历史记录后仍可再次返回。
   e. 点击关闭按钮或按 Esc 关闭整个抽屉，不返回当前审批申请。
5. 申请编号为历史记录的唯一查询键；点击"查看"时按申请编号定位记录。
6. 历史范围为同一 XaaS 订阅 ID、本次之前已提交的全部申请，按申请时间正序排列。
   a. 第一次变更：展示首次申请记录。
   b. 第二次变更：展示首次申请记录 + 第一次变更记录。
   c. 依此类推，每次变更叠加展示截至上一次的历史记录。
7. 延期场景不设特例，列表最后一条即"延期前"的记录。
8. 仅按订阅 ID 关联，不按产品、模块二次过滤。

#### 3、字段校验规则

1. 关联键必须为 XaaS 订阅 ID，不得使用订阅名称。
2. 历史记录必须包含申请编号；缺少申请编号时"查看"按钮置灰，并提示"缺少申请编号，无法查看"。
3. 申请编号展示为等宽字体、单行展示，不换行；申请编号在记录内唯一。
4. 展示值为申请提交时的快照，不随授权现状变化。
5. 不再展示"模块""参数规格"；历史参数信息通过"查看"进入详情查看。
6. 无历史记录时显示"暂无关联申请记录"。
7. 历史记录较多时全部列举，区域支持滚动，不截断。
8. 本模块为只读展示，无用户输入项。

#### 4、提交逻辑处理

1. 不涉及表单提交。
2. "查看"按钮只做详情跳转，不改变当前审批动作、审批意见与审批流程。
3. 关联记录读取失败时展示"关联记录加载失败，请重试"，不阻断主审核流程；重试为手动触发，不自动轮询。
4. 历史详情读取失败时提示"历史申请详情加载失败，请重试"，不影响当前审批页。

#### 5、验收标准

1. 分组与折叠：
   a. 变更 / 延期记录展示"关联此前申请记录"区，按订阅分组，组头为"产品族 / 订阅名称"。
   b. 默认展开；点击组头收起该组表格，再次点击展开；多组各自独立。
   c. 不再展示独立的"查看关联此前申请记录"入口行。
2. 表格内容：
   a. 组内表头为"申请编号 / 申请人 / 区域 / 申请时间 / 授权产品 / 到期时间 / 操作"。
   b. 不再展示"模块""参数规格"列。
   c. 申请编号单行展示，不换行。
3. 查看跳转：
   a. 每行"操作"列展示"查看"按钮。
   b. 点击"查看"打开对应申请编号的历史授权记录详情，详情中的申请编号与列表一致。
   c. 首次开通历史记录按"未开通 / —"口径展示；变更历史记录按当次变更前后值展示。
   d. 缺少申请编号时"查看"按钮置灰并提示。
   e. 历史详情提供"返回审核申请"入口，返回后仍停留当前审批申请，审批意见、审批决定、展开状态与滚动位置不丢失。
4. 边界：
   a. 首次变更展示首次申请记录；后续变更叠加展示历史。
   b. 首次开通记录不展示关联记录区。
   c. 读取失败有提示且不阻断审批。

### 4.1.3 首次开通记录的配置变更展示

#### 1、初始状态

1. 首次开通的 XaaS 授权记录，在"订阅授权明细"下展示"配置变更"表。
2. 授权有效期行：变更前"未开通"，变更后为申请有效期区间。
3. 模块分组默认收起，摘要为"N 项变更 · 至 YYYY-MM-DD"。

#### 2、交互逻辑说明

1. 系统按申请动作识别首次开通记录，渲染与 4.1.1 相同的配置变更表。
2. 模块分组按订阅逐条展示；点击展开 / 收起。
3. 展开后展示模块状态、版本、产品参数、授权至；无对应字段不生成空行。
4. 多订阅记录逐条分组（如"PC 终端""服务器"）。
5. 首次开通记录无历史申请，不展示关联记录入口。

#### 3、字段校验规则

1. 变更前值统一为"未开通"或"—"：
   a. 授权有效期、模块状态、授权至使用"未开通"；
   b. 版本、产品参数使用"—"。
2. 变更后值为申请值；日期格式为 `YYYY-MM-DD`。
3. 订阅无某参数时不生成对应行，不显示空行。
4. "N 项变更"按展开项数量计数，包含模块状态、授权至。
5. 本模块为只读展示，无用户输入项。

#### 4、提交逻辑处理

1. 不涉及表单提交。
2. 审批动作沿用现有审批流程。
3. 不写回授权数据；审批通过后按现有开通流程生成授权。

#### 5、验收标准

1. 配置变更表展示：
   a. 首次开通记录展示配置变更表，授权有效期"未开通 → 申请有效期"。
   b. 模块分组默认收起，摘要含"N 项变更"与"至"日期。
   c. 变更后值深蓝加粗，变更前值普通文本。
2. 展开内容与边界：
   a. 展开后模块状态"未开通 → 已开通"、版本"— → 版本号"、参数"— → 申请值"、授权至"— → 到期日"。
   b. 多订阅分组正确，各自展示参数与授权至。
   c. 首次开通记录不展示关联此前申请记录。

## 5. 成功度量

| 指标 | 定义 | 基线 | 目标 |
| :--- | :--- | :--- | :--- |
| 审批平均时长 | 变更 / 延期申请从提交到审批完成的中位时长 | 待采集 | 下降 ≥ 20% |
| 变更类退回率 | 因"变更不清"被退回的申请占比 | 待采集 | 下降 ≥ 30% |
| 审批人满意度 | 针对变更可视化的问卷评分（5 分制） | 待采集 | ≥ 4.0 |

基线采集责任人与采集时间待确认（见第 7 节）。
