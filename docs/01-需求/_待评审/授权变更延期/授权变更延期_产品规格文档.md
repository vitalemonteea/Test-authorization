## 1. 背景与问题陈述（Why）

当前客户可通过**测试授权申请平台**提交试用申请；开通后如有变动，可**再次提交申请**来延期或追加已开通的授权。

**核心问题**：再次提交的申请内容不完整——审批人在审核时**无法识别本次相对已开通授权到底改了什么**（延长了多久、规格调了多少），只能凭经验或线下沟通去核对，造成审批效率低、易漏审、易退回。

**本次目标**：在"变更 / 延期试用"申请场景中，让变更内容对审批人**可见、可读、可追溯**——既在表单内高亮变更点（新值 + 原值），又支持查看关联的此前申请记录。

---

## 2. 目标与非目标

### 目标

- 审批人在审核页可一眼识别本次申请的变更点（变更字段、变更前后值）。
- 审批人可下钻查看本次申请关联的此前授权申请记录，获得历史上下文。

### 非目标（Non-goals）

- 不改造申请提交流程本身，不改变"再次提交申请"的入口与字段填写方式。
- 不做审批流引擎改造（审批动作、审批人分配规则不在本次范围）。
- 不覆盖"首次申请"场景的展示逻辑（该场景无"原值"可对比）。
- 不做变更内容的自动校验或冲突拦截（仅展示，不阻断）。
- 不改申请人提交页的既有展示（申请人端"新值 + 原值"对比已存在，本次仅补审批端能力）。
- 不覆盖产品授权、解决方案/设备授权记录的变更展示；现有产品授权"配置变更"表保持原样。
- 不引入字段级权限；高亮与关联记录的可见性由审批页权限控制。

| 授权审批人 | 审核测试授权申请的人员（具备授权审批权限）          |
| 申请人   | 提交授权申请的人员（客户 / CSM / 销售，代客户提交） |

### 术语

| 术语        | 说明                                                   |
| --------- | ---------------------------------------------------- |
| 变更 / 延期试用 | 申请动作之一，表示在已开通授权基础上发起部分内容变更                           |
| 申请动作      | 表单层动作，取值「变更 / 延期试用」；仅用于展示判定，不用于审批路由                  |
| 审批场景      | 路由层细分场景（延期 / 授权变更 / 新增模块等）；仅用于审批流，不影响展示判定            |

## 4. 功能规格

### EP-01 授权变更 / 延期可视化

> epic 目标：让"变更 / 延期试用"申请对审批人透明，消除"重提申请内容不完整"导致的审批盲区。

本次仅覆盖 **XaaS 订阅记录**；产品授权、解决方案/设备授权的变更展示不在范围内。

---

#### Feature 1.1 变更点高亮展示

> **功能目标**：当申请动作为"变更 / 延期试用"时，按 XaaS 订阅逐条将变更字段的**新值在前、原值括注在后**高亮展示，使审批人无需线下核对即可识别变更内容。

##### US-01-01 审批人查看变更点高亮

> 作为**授权审批人**，我希望在审核"变更 / 延期试用"申请时，表单中能直接看到各字段的变更点（新值在前、原值括注在后），以便于快速识别本次申请相对已开通授权的具体变更内容，避免遗漏审批信息。

**【操作步骤】**

1. 审批人进入"变更 / 延期试用"申请审核页。
2. 系统识别申请动作，并按 XaaS 订阅逐条比对当前已生效授权与该订阅的差异。
3. 对发生变更的字段，按"新值 +（原值）"格式渲染并高亮；未变更字段保持原展示。
4. 审批人据此完成审核。

**【验收标准】**（必填）

- 当申请动作 = "变更 / 延期试用" 时触发；首次申请、"新购"等无原值场景不触发。**判定只读申请动作，不读审批场景。**
- 当发生**到期时间变更**时，"到期时间"字段展示格式为：  
  `<新到期日>（原到期时间：<原到期日，格式 YYYY-MM-DD>）`  
  示例：`2026-12-31（原到期时间：2026-06-30）`。
- 当发生**规格变更**时，按字段逐项展示，每个变更字段独立括注：  
  `<字段名>：<新值>（原：<原值>）`  
  示例：`日志接入数量：2 亿条（原：1 亿条）`、`带宽：10M（原：5M）`。
- **多订阅**：每个订阅独立一组对比，组头为"产品族 + 订阅名称"；新增订阅无原值，直接展示新值。
- **模块增删**：`新增模块：<模块名>（原：未开通）`；`移除模块：<模块名>（原：已开通）`（是否允许移除模块待确认，见第 7 节）。
- **参数增删**：`新增参数：<字段名>：<新值>`；`移除参数：<字段名>（原：<原值>）`。
- 未发生变更的字段**不**加括号括注，保持原展示。
- 变更点以**值级高亮**呈现：新值沿用审批页既有强调样式（当前为 `.target` 深蓝加粗 `#003f9e`），原值用灰色括注；不新增背景色或图标，与未变更字段区分。
- **权限**：高亮仅对具备授权审批权限的角色可见，可见性由审批页权限控制；申请人提交页维持现有"新值 + 原值"对比，不展示"审批专用"标识；不做字段级权限。
- **对比源**：以订阅 `meta` 参数为唯一对比源，`spec` 仅作摘要展示，避免同一值两处对比。

**【补充说明】**

- 高亮对照基准取"当前已生效授权"的字段值（已确认）。
- 已生效 = 审批通过且已生效的最新授权快照；上一笔变更审批通过但未生效的，不进入基准。
- 申请人提交页当前已有"新值 + 原值"对比展示，本次不改动申请人端（已确认）。
- 可同时发生"到期时间变更 + 规格变更"，两处独立高亮。
- 规格字段以字段名为键逐项对比，不整体替换对比。
- 参与对比的字段白名单：
  - 授权有效期；
  - 订阅 `meta` 中的业务参数；
  - 模块 / 订阅增删。
- 不参与对比的字段：订阅状态、授权码、租户 ID、交付信息、申请理由、附件、联系人。
- XaaS 字段映射：授权产品 → 订阅 family / 产品；模块 → 订阅 name；参数规格 → 订阅 `meta`；到期时间 → 订阅有效期。

**【异常场景】**

- 原值缺失（历史未记录该字段）：仅展示新值，原值括注显示 `（原值：暂无记录）`。
- 申请动作 = "新购 / 首次申请"（无原值可对比）：不触发高亮逻辑，按原样式展示。
- 同期存在多次变更：原值统一取"当前已生效授权"的值，而非上一次申请的值；**上一笔变更审批通过但未生效的，不进入基准，并在审批页提示"该订阅存在未生效的变更申请"**。
- 上一笔申请被驳回：不改变原值基准。
- 订阅已过期：原到期时间取历史到期日，并在审批页标注"已过期 N 天"。
- 订阅已终止 / 回收：在提交入口拦截，不进入审批展示层。
- 过期后按"重新开通"再次申请：按申请动作判定，申请动作为"延期"时仍触发高亮，原值取历史到期日；如业务对"重新开通"另有定义，按第 7 节待确认项调整。
- 原值格式异常（如日期非法）：原值括注显示 `（原值：数据异常）`，不阻断提交与展示。

#### Feature 1.2 关联此前申请记录

> **功能目标**：按 XaaS 订阅分组展示当前申请所关联的此前授权申请记录，默认收起、可展开，为审批人提供历史上下文。

##### US-01-02 审批人查看关联此前申请记录

> 作为**授权审批人**，我希望在审核"变更 / 延期试用"申请时，能查看本次申请所关联的此前授权申请记录（默认收起、可展开），以便于了解历史授权上下文，结合原记录做出准确审批决策。

**【操作步骤】**

1. 审批人进入"变更 / 延期试用"申请审核页。
2. 关联记录区**默认收起**，展示入口（如"查看关联此前申请记录"）。
3. 审批人点击展开，按订阅分组查看该订阅关联的此前申请记录字段。
4. 审批人收起或继续审核。

**【验收标准】**（必填）

- 关联记录区**默认收起**，显示入口文案 `查看关联此前申请记录`（点击展开 / 再次点击收起）。
- **关联维度**：同一 **XaaS 订阅 ID**；不得使用订阅名称作为关联键（名称可变更）。
- 展开后按订阅分组，组头为"产品族 + 订阅名称"；每组独立展开 / 收起。
- 展开后展示字段：**申请人、区域、申请时间、授权产品、模块、参数规格、到期时间**。
  - 授权产品：订阅 family / 产品；当次申请的所有产品均列举。
  - 模块：订阅 name；当次申请的所有模块均列举。
  - 参数规格：订阅 `meta` 参数，展示当次申请的完整参数，变更点加标记。
  - 到期时间：订阅有效期。
- **展示时点**：申请提交时的快照值，不随授权现状变化。
- **历史范围**：该订阅下、本次申请之前、已提交的全部申请记录，按申请时间正序排列。
  - 第一次申请变更：展示**首次申请**记录。
  - 第二次申请变更：展示**首次申请**记录 + **第一次变更申请**记录。
  - 依此类推，每次变更仅叠加展示截至上一次的历史记录。
- **延期场景不设特例**：同样展示该订阅截至本次之前的全部历史记录，列表最后一条即"延期前"的记录。
- 仅展示与当前申请属于同一订阅 ID 的记录；"相关"的判定不再按产品、模块二次过滤。

**【补充说明】**

- 字段展示与"变更高亮"互补：高亮看"变了什么"，关联记录看"历史全貌"。
- 多订阅申请按订阅分组展示，避免不同订阅的历史混在一起。

**【异常场景】**

- 无历史申请记录（系统无关联）：展示 `暂无关联申请记录`。
- 历史记录产品 / 模块较多：全部列举，区域支持滚动，不截断；默认展示高度与是否记住展开状态待确认（见第 7 节）。
- 关联记录读取失败：展示 `关联记录加载失败，请重试`，不阻断主审核流程；重试为手动触发，不自动轮询。
- 申请动作非"变更 / 延期"（如新购）：不展示关联记录入口。

## 5. 成功度量

| 指标     | 定义                   | 基线  | 目标       |
| ------ | -------------------- | --- | -------- |
| 审批平均时长 | 变更/延期申请从提交到审批完成的中位时长 | 待采集 | 下降 ≥ 20% |
| 变更类退回率 | 因"变更不清"被退回的申请占比      | 待采集 | 下降 ≥ 30% |
| 审批人满意度 | 针对变更可视化的问卷评分（5 分制）   | 待采集 | ≥ 4.0    |

基线采集责任人与采集时间待确认（见第 7 节）。

## 6. 风险与依赖

| 类型   | 说明                                                                                          |
| ---- | ------------------------------------------------------------------------------------------- |
| 数据依赖 | 变更高亮的"原值"依赖**已生效授权数据**的准确存储；原值缺失将退化为"暂无记录"。**XaaS 订阅 ID 必须稳定，不得使用订阅名称作为关联键。**            |
| 字段映射 | 申请平台字段与已生效授权字段须保持一致命名与口径，否则对比错位。XaaS 以订阅 `meta` 的 label 和单位为准；"2 亿条"与"2"不能直接对比。               |
| 权限   | 高亮与关联记录仅对审批权限角色可见，可见性由审批页权限控制；不做字段级权限。                                                    |
