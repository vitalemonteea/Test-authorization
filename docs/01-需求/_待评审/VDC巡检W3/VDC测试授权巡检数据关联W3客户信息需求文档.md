## 1. 需求背景

一线项目实施人员使用纪元平台客户端对VDC环境执行巡检。巡检完成后，客户端将VDC配置项、环境运行指标等数据上报至纪元平台服务端。服务端解析上报数据，识别不符合规范标准的配置，并通知一线实施人员提前优化调整，落实最佳实践，前置规避故障，减少后续400热线、研发团队的排查投入。

当前不同授权场景的客户信息获取情况如下：

| 授权场景 | 客户信息获取现状 | 对巡检业务的影响 |
| --- | --- | --- |
| VDC正式授权 | 可通过订单系统或授权平台获取客户基础信息 | 沿用现有客户信息关联逻辑 |
| VDC测试授权（POC项目） | 授权平台、订单系统无法查询到对应客户信息；测试授权统一在W3系统申请 | 巡检上报数据无法关联客户主体，影响异常配置定向通知 |

因此，需要使用巡检上报的测试授权ID查询W3系统，补齐POC项目的客户及授权信息。

## 2. 需求目标与范围

1. 纪元平台服务端收到VDC巡检数据后，按授权类型选择客户信息获取路径。
2. 正式授权沿用现有订单系统、授权平台查询逻辑；测试授权以授权ID查询W3系统。
3. W3系统提供查询接口，返回客户及授权相关的12项字段，供纪元平台完成巡检数据与POC客户信息关联。
4. 本需求交付范围为W3查询接口及纪元平台调用、数据关联能力；异常配置检测和整改通知由纪元平台现有业务流程承接，通知对象映射规则见第5节。

---

## 3. 业务价值

1. 补齐POC测试授权场景的巡检客户信息，为覆盖正式授权与测试授权的VDC巡检配置校验提供数据基础。
2. 支撑重点项目、大项目异常配置的定向整改通知，推动一线提前调整配置，降低后续故障发生概率。
3. 减少故障发生后400热线、研发团队的排查工作量，节约人力投入。

## 4. 功能模块需求

### 4.1 授权类型分流与巡检数据关联

#### 1、初始状态

1. 纪元平台服务端已接收到VDC巡检上报数据，进入客户信息关联环节。
2. 正式授权客户信息通过现有订单系统、授权平台查询逻辑获取。
3. 测试授权客户信息由W3查询接口提供，查询依据为本次巡检上报的授权ID。
4. 本模块为服务端处理流程，无新增页面或人工操作入口。

#### 2、交互逻辑说明

1. 纪元平台根据授权类型进行分流：
   - 正式授权：执行现有客户信息获取与关联流程。
   - 测试授权（POC）：提取授权ID，调用第4.2节定义的W3查询接口。
2. W3查询成功后，将返回的客户及授权信息与本次巡检数据建立关联，供后续异常配置定向通知使用。
3. 对异常结果，建议按以下规则处理，具体规则在评审时确认：
   - 授权类型无法识别、授权ID缺失、未查询到记录或接口调用失败时，保留巡检数据，记录关联失败原因，不标记为关联成功。
   - 返回数据无法明确对应唯一授权记录，或客户名称缺失时，不自动关联客户，避免错误匹配。
   - 客户关联未完成时，不使用推测的客户或人员信息执行定向通知。

#### 3、字段校验规则

1. 测试授权查询必须提供巡检上报的授权ID；为空时无法发起W3查询。
2. 授权ID为查询匹配依据，不使用客户名称、设备SN等字段替代查询。
3. 客户名称是实现本需求关联目标的必要信息；建议缺失时判定为客户关联未完成。
4. 授权类型应能区分正式授权和测试授权；具体数据来源、字段及枚举值待确认。
5. 授权ID与返回授权记录的一致性校验方式，依据第5节确认后的标识映射关系确定。

#### 4、提交逻辑处理

1. 触发条件：纪元平台服务端收到VDC巡检数据并进入客户信息关联环节。
2. 处理流程：识别授权类型 → 选择查询路径 → 获取客户及授权信息 → 校验关联结果 → 保存与本次巡检数据的关联关系。
3. 测试授权查询成功且满足关联条件后，保存返回的客户及授权信息，供纪元平台后续业务使用。
4. 建议关联失败时保留授权ID及失败原因，便于定位问题；重试与补偿机制由双方在联调方案中明确。

#### 5、验收标准

1. 上报数据为正式授权时，纪元平台通过现有订单系统、授权平台逻辑获取客户信息。
2. 上报数据为测试授权且包含有效授权ID时，纪元平台使用该授权ID调用W3查询接口。
3. W3返回有效客户及授权信息后，可在本次巡检数据中追溯其对应客户和授权记录。
4. 关联完成后，纪元平台异常配置处理流程可读取关联信息，作为定向通知的数据依据。
5. 异常处理建议经评审确认后，补充并执行以下场景验收：授权类型未知、授权ID缺失、未查到记录、接口调用失败、匹配结果不唯一、客户名称缺失；预期均不得形成错误客户关联。

### 4.2 W3测试授权客户及授权信息查询接口

#### 1、初始状态

1. W3系统中已存在VDC测试授权申请及对应的客户、授权信息。
2. 接口调用方为纪元平台服务端，数据提供方为W3系统。
3. 接口支持以授权ID查询对应的POC项目客户及授权相关信息。
4. 本模块为系统间查询接口，无页面展示或人工提交操作。

#### 2、交互逻辑说明

1. 纪元平台提交授权ID后，W3系统查询对应授权记录及所属申请信息。
2. 匹配成功后，返回客户及授权信息，字段清单见本节“字段校验规则”。
3. 接口需区分查询成功、入参不合法、记录不存在及系统处理失败等结果，便于纪元平台分别处理；具体响应结构和错误码在接口设计时明确。
4. 按授权ID唯一匹配记录；如实际数据存在多条匹配，需按第5节确认的映射规则处理，不任意选取记录返回。

#### 3、字段校验规则

1. 接口入参如下：

   | 参数名 | 必填 | 说明 | 校验要求 |
   | --- | --- | --- | --- |
   | 授权ID | 是 | 巡检上报的VDC测试授权唯一标识 | 非空；具体格式、长度及对应W3字段由双方联调确认 |

2. 接口返回字段如下。以下为业务字段清单，接口字段编码、类型、空值规则以双方确认的接口契约为准。

   | 序号 | 字段名称 | 业务说明 |
   | --- | --- | --- |
   | 1 | 客户名称 | 当前测试授权对应的POC客户名称，用于识别客户主体 |
   | 2 | 申请编号 | 当前授权所属的W3申请编号 |
   | 3 | 授权类型 | 当前授权记录的业务类型；具体枚举待确认 |
   | 4 | 产品线/方案 | 当前授权对应的产品线或方案 |
   | 5 | 版本 | 当前授权对应的产品版本 |
   | 6 | 设备ID/云图ID | 当前授权关联的设备ID或云图ID |
   | 7 | 设备SN | 当前授权关联的设备序列号 |
   | 8 | 云授权ID | 当前授权对应的云授权标识；与入参授权ID的关系待确认 |
   | 9 | 区域 | 当前授权申请记录中的区域信息；具体业务口径待确认 |
   | 10 | 授权有效期 | 当前授权的有效期限；返回起止时间还是其他形式待确认 |
   | 11 | 申请人 | 当前授权申请的申请人信息；人员标识及返回形式待确认 |
   | 12 | 申请时间 | 当前授权申请在W3系统中的申请时间 |

3. 返回信息应来源于同一授权记录及其所属申请，避免将同一客户其他申请或其他设备的信息混合返回。
4. 设备ID/云图ID、设备SN、云授权ID等字段是否可能为空，按实际授权场景确认，不默认要求全部有值。
5. 时间字段的格式、时区以及“授权有效期”的起止边界需在接口契约中统一。

#### 4、提交逻辑处理

1. 触发条件：W3系统收到纪元平台发起的查询请求。
2. 处理流程：校验入参 → 按授权ID查找授权记录 → 获取所属申请及客户信息 → 组装12项业务字段 → 返回查询结果。
3. 入参不合法、记录不存在或系统处理失败时，返回可区分的处理结果及原因，供纪元平台记录和处理。
4. 本接口为只读查询，不创建或修改W3申请、审批及授权记录。
5. 接口地址、请求方式、鉴权、超时及重试约定由双方在联调方案中明确。

#### 5、验收标准

1. 使用已存在的VDC测试授权ID调用接口，可准确返回对应POC客户及授权信息。
2. 返回内容包含约定的12项业务字段；各字段的值及空值情况符合双方确认的接口契约。
3. 对照W3源记录核验，返回的客户名称、申请编号、设备信息、申请人及其他字段均属于该授权及其所属申请。
4. 授权ID为空时，接口返回入参校验失败；授权ID不存在时，接口返回记录不存在，两个结果可区分。
5. 系统处理失败时，接口返回明确的失败结果，纪元平台不得将其识别为查询成功。
6. 接口调用前后，W3申请、审批及授权记录内容保持一致。

## 5. 待确认事项

以下事项不影响本次需求整理，但需在接口开发与联调前确认：

1. **授权标识与匹配关系**：巡检上报的“授权ID”对应W3哪个字段，是否等同于“云授权ID”；续期或变更后能否唯一定位授权记录；匹配不唯一时如何处理。
2. **授权类型与字段契约**：纪元平台从何处获取正式/测试授权分类，返回字段“授权类型”采用何种业务口径；同步确认12项字段的编码、格式、空值规则及接口调用、异常和补偿约定。第4.1节标为“建议”的异常规则需在此一并评审。
3. **定向通知对象映射**：W3申请人是否就是需要接收通知的一线实施人员，返回人员信息能否映射至纪元平台现有通知对象。当前字段清单未包含客户唯一编码及通知联系方式；如纪元平台关联客户或发送通知依赖这些信息，需确认现有映射能力是否满足，再决定是否补充字段。
