## 需要业务确认的事项

1. **产品测试平均时长的统计对象**：按设备还是按申请平均？统计本周期全部申请还是已通过申请？同设备延期/重复申请是否只取最新累计时长？建议按设备去重后计算，避免频繁延期的设备重复进入平均值；此建议尚未作为业务规则执行。
2. **异常设备指标是否本期启用**：若保留，需明确哪些情况算异常、设备统计范围、去重标识与比例分母。也可先列为后续项；当前原文无法确定这些规则。
3. **运营目标与责任设置**：各核心指标的管理目标、预警阈值、观察频率及负责人待补。暂未确认不影响看板结构评审，也不触发演示预警。

最新周表替换已经确认，无需再次确认。审批通过率暂沿用原方案“通过申请 / 进入审批申请”，不另改已结束审批分母；样本不足先留空。

## 后续向开发取数的最小清单

以下是建议的数据交付字段，不代表已经存在接口或已经确认新的业务规则。可从平台申请、审批和执行日志关联取得，不再索取另一份旧汇总。

| 数据组 | 必要字段 | 解决的问题 |
| --- | --- | --- |
| 申请及维度明细 | 申请编号、创单/成功提交时间、产品线、授权类别、场景、申请类型、平台入口、客户类型、区域、是否需审批 | 日/月趋势、维度拆解与真实申请量 |
| 填单与提交事件 | 旅程标识、申请编号（成功后关联）、事件类型、发生时间、失败字段/原因、接口与结果码 | 转化、填写耗时、前端校验和后端失败原因 |
| 审批日志 | 申请编号、实际节点标识/名称、进入/结束时间、通过/拒绝/进行中结果、拒绝原因 | 审批率、节点卡点、均值与分位数 |
| 自动执行与激活日志 | 申请/授权/设备标识、实际节点、是否应执行/适用、开始/结束时间、成功/失败、错误原因、执行尝试标识及最终结果 | 客户创建、授权生成、设备激活的独立结果与耗时；识别重试与终态 |
| 测试历史 | 稳定设备标识、历史实际测试时长、本次申请时长、申请关联及产品线 | 口径确认后计算产品测试平均时长 |
| 异常规则结果 | 经业务确认的规则、设备标识、命中时间与结果 | 规则确认后计算异常设备比例 |
